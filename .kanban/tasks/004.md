## Задача

CPU-примитивы x86-64: GDT, TSS, IDT с IST и обработчики исключений.
База: ветка `task/011` (в ней уже есть `BootInfo`, консоль и panic-заглушка из T1/T2).

### Что сделать

1. **GDT**: сегменты ядра (code64, data), TSS-дескриптор, загрузка `lgdt`, перезагрузка
   `cs`/`ss`/`ds` (far return / `retfq`), обновление `star`/`lstar` заделом под syscall.
2. **TSS**: `rsp0` (стек для прерываний из ring0 не нужен, но поле заполнить),
   массив IST: `ist[1]` — double fault, `ist[2]` — NMI, `ist[3]` — page fault.
   Стеки IST — отдельные статические массивы (по 8 КиБ, выровнены 16).
3. **IDT**: 256 векторов; 0–31 — исключения с обработчиками, у векторов с кодом ошибки
   (8, 10–14, 17, 21, 29, 30) — обёртки, снимающие error code со стека;
   32–255 — заглушка, печатающая «unexpected vector N» и останавливающая систему.
4. **Дамп исключения**: имя вектора, error code, `rip`, `cs`, `rflags`, `rsp`, `ss`,
   `cr2` для #PF, и регистры общего назначения (rax..r15). Затем `hlt` в цикле.
5. **Тесты-смоуки**: `int3` (вектор 3) и деление на ноль (вектор 0) дают дамп и остановку,
   без тройной ошибки и без перезагрузки.

### Важно

- **Прерывания не включать** (`sti` запрещён): обработчиков для 32+ нет, а таймер без
  IDT-записи даст тройную ошибку. Это осознанно до задачи планировщика.
- Обработчики должны быть `extern "x86-interrupt"` (или эквивалент с корректным
  выравниванием стека), не обычные функции.
- Модуль — `kernel/src/arch/x86_64/**`, регистрация из `main.rs` одной строкой.

### Приёмка

- `make qemu`: `int3` в тестовом режиме печатает `EXCEPTION #BP ... rip=...` и останавливается;
- деление на ноль печатает `EXCEPTION #DE` с дампом;
- `make smoke` остаётся зелёным (11 маркеров + debugcon);
- `cargo check --target x86_64-unknown-none` зелёный.

### Границы

`kernel/src/arch/x86_64/**`, одна строка вызова в `kernel/src/main.rs`.
`console/`, `boot/`, `libs/` — не переписывать.
