## Задача

P2: память и RAG прототипа. База — ветка task/015 (прототип уже работает: modeld + консоль).

Сделать по docs/PROTOTYPE.md §4 и §5, форматы — по docs/ARCHITECTURE.md §5 (использовать `libs/memfmt`, он уже влит).

### Что сделать

1. **Эпизодическая память**: заменить плоский NDJSON-лог воркспейса на сегменты через
   `libs/memfmt` (заголовок + записи с magic/len/crc/seq). Восстановление после обрыва —
   resync-сканом (в memfmt есть). Сессия = набор сегментов.
2. **Семантическая память**: факты `{scope, subject, key, value, source, author, confidence,
   state, ttl}` с провенансом. Хранение — в `memory/facts.jsonl` воркспейса (атомарная запись).
   Автор: `Human` (через `/remember`) или `Model` (позже, статус unverified).
3. **Индекс**: BM25 по записям сегментов и фактам, перестраивается сканом при старте,
   инкрементально пополняется. Никаких эмбеддингов.
4. **Сборка контекста с бюджетом**: system-часть воркспейса + pinned-факты + хвост сессии +
   извлечённые эпизоды; бюджет по токенам (оценка chars/4, точные — из usage).
   В `/status` показывать состав: system/facts/tail/retrieved в токенах.
5. **RAG по файлам**: чанкование текстов из `files/` (например по 800 символов с перекрытием 100),
   индексация, поиск при вопросе, вставка top-k в контекст. Ответ должен ссылаться на файл
   и фрагмент (в консоли печатать `[files/report.md §2]`).
6. **Команды**: `/remember subject key = value`, `/memory <query>` (поиск с провенансом),
   `/forget <id>` (с подтверждением и записью в аудит-сегмент), `/status` (состав контекста).

### Приёмка

- `cargo test` — зелёный, добавить тесты: восстановление сегмента после обрезки, поиск BM25

- `/remember` → перезапуск → факт на месте и попадает в контекст (видно в `/status`);
- RAG: положить файл в `files/`, задать вопрос по его содержимому → ответ со ссылкой на фрагмент;
- бюджет контекста не превышается (при длинном файле — усечение с записью в `/status`);
- `cargo check -p aios-kernel --target x86_64-unknown-none` в корне не сломан.
