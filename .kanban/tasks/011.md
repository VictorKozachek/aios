## Задача

Структура `BootInfo` и диагностика ранней загрузки (docs/ARCHITECTURE.md §3, docs/PLAN-M0.md T2).

**Зависимость:** начинать после слияния #001 (каркас сборки и загрузка) в `v0.1` — иначе нет Makefile и образа.
**Объединена с #003** (дубликат удалён): вся работа по T2 идёт здесь.

### Что сделать

1. `BootInfo`: memmap, hhdm, paging_mode, framebuffer, rsdp, tsc_hz, entropy, modules.
2. Парсинг запросов Limine base revision 3: memmap, hhdm, framebuffer, rsdp, tsc, mp.
3. Три канала диагностики: COM1 (0x3F8), framebuffer-писатель с прокруткой, debugcon (0xE9).
4. Panic-обработчик: сообщение + остановка, чтобы отладка была возможна.

### Приёмка

В логе QEMU есть: версия Limine, карта памяти (usable MiB), HHDM base, адрес RSDP,
число ядер, частота TSC; на экране тот же текст.

### Границы

`kernel/src/boot/**`, `kernel/src/console/**`, `libs/bootinfo/**`.
Makefile и build/ — не трогать (это #001).

### 1. `libs/bootinfo` — arch-нейтральный тип, тестируется на хосте

Крейт `no_std`, без зависимостей и без аллокатора: фиксированные массивы, т.к. аллокатора
на входе в ядро ещё нет.

```rust
pub const MAX_MEMMAP: usize = 128;   // в QEMU ~20–30 записей
pub const MAX_MODULES: usize = 8;
pub const ENTROPY_BYTES: usize = 32;

pub struct MemmapEntry { pub base: u64, pub length: u64, pub kind: MemmapKind }

pub enum MemmapKind { Usable, Reserved, AcpiReclaimable, AcpiNvs, BadMemory,
                      BootloaderReclaimable, ExecutableAndModules, Framebuffer, Other(u64) }

pub struct Framebuffer { pub addr: u64, pub width: u32, pub height: u32, pub pitch: u32,
                         pub bpp: u16, pub memory_model: u8,
                         pub red: Channel, pub green: Channel, pub blue: Channel }

pub struct Module { pub addr: u64, pub size: u64, pub flags: u32 }

pub enum PagingMode { FourLevel, FiveLevel, Unknown }
pub enum EntropySource { Rdrand, TscJitter, None }

pub struct BootInfo {
    pub memmap: [MemmapEntry; MAX_MEMMAP], pub memmap_len: u16,
    pub memmap_truncated: bool,
    pub hhdm: Option<u64>,
    pub paging_mode: PagingMode,
    pub framebuffer: Option<Framebuffer>,
    pub rsdp: Option<u64>,
    pub tsc_hz: Option<u64>,
    pub entropy: [u8; ENTROPY_BYTES], pub entropy_source: EntropySource,
    pub modules: [Module; MAX_MODULES], pub modules_len: u8,
    pub cpu_count: u64, pub bsp_lapic_id: u32,
}
```

Методы: `usable_bytes()`, `bytes_of_kind()`, `is_sane()` (memmap не пуста, есть usable,
HHDM выровнен на 2 МиБ, RSDP лежит в reserved/acpi-диапазоне), `iter_memmap()`.
Тесты на хосте: классификация видов, сумма usable, переполнение при `len > MAX_MEMMAP`
(флаг `truncated`), `is_sane()` на карте, похожей на QEMU, и на испорченных данных.

### 2. `kernel/src/boot/` — сбор из протокола Limine base revision 3

После слияния #001 в base уже есть черновик `boot/{limine,mod}.rs` — он становится
основой, я его дополняю, а не переписываю:

1. Запросы Limine: оставить memmap, hhdm, framebuffer, rsdp, tsc, mp, bootloader info;
   **добавить** `modules` и `paging_mode` (x86_64), проверку base revision — уже есть.
2. `collect() -> BootInfo`: копирование в фиксированные массивы с ограничением по `MAX_*`;
   при переполнении — `memmap_truncated = true` (в лог уходит предупреждение, не паника).
3. `entropy.rs`: 32 байта из RDRAND (CPUID.1:ECX[30]); fallback — splitmix64 по дельтам
   RDTSC (64 итерации); источник пишется в `entropy_source` и в лог.
4. `report.rs`: печать `BootInfo` — версия Limine, карта памяти (usable MiB + число
   записей), HHDM base, paging mode, RSDP, CPUs/BSP LAPIC, TSC (MHz и Hz), источник
   энтропии, модули, геометрия framebuffer.

### 3. `kernel/src/console/` — три канала и panic

- serial (COM1 0x3F8): init 115200 8N1, `\n` → `\r\n`;
- debugcon (0xE9) — уже есть;
- framebuffer: шрифт 8×16, прокрутка при переполнении, `\t`;
- panic: `PanicInfo` (включая `location()`) во все инициализированные каналы и `hlt`-цикл.
  Карта символов (`PLAN-M0` T2) — после T3, когда появится IDT: сейчас точное место
  паники даёт `location()`, а разбор адресов без символов бессмыслен.

### 4. `kernel/src/main.rs`

Порядок из ARCHITECTURE §3: ранняя консоль (serial + debugcon) → проверка base revision →
framebuffer → `collect()` → `report()` → halt. Структуру из #001 сохраняю.

### 6. Риски и решения

| Риск | Решение |
|---|---|
| Limine отдаёт `tsc_hz = 0` в QEMU | калибровка по PIT (канал 2, ~10 мс), иначе `None` + предупреждение в логе |
| Нет RDRAND под TCG | fallback на TSC-jitter, честная пометка `EntropySource::TscJitter` |
| Framebuffer не 32 bpp | работаем только с 32 bpp (QEMU XRGB8888), иначе остаются serial+debugcon |
| Конфликт с #001 в `boot/` и `console/` | после merge rebase `task/011` на `v0.1`, правки только в своих файлах |
| Переполнение фиксированных массивов | `truncated`-флаг + предупреждение, без паники |

## Разделение T2 (решение оркестратора)

T2 делится на две части, чтобы исполнитель не простаивал:

| Часть | Где | Когда | Приёмка |
|---|---|---|---|
| **T2a — arch-нейтральный `BootInfo`** | `libs/bootinfo/**` (каркас в `v0.1`) | **сейчас** | `cargo test -p bootinfo` зелёный; `cargo check --target x86_64-unknown-none -p bootinfo` зелёный; типы покрывают таблицу полей ARCHITECTURE §3; валидация отвергает битые данные |
| **T2b — интеграция в ядро** | `kernel/src/boot/**`, `kernel/src/console/**` | после слияния #001 | лог QEMU: версия Limine, usable MiB, HHDM, RSDP, число ядер, TSC; тот же текст на экране |

Что должно быть в T2a:

1. `BootInfo`: карта памяти (список диапазонов с типами usable/reserved/acpi/mmio),
   `hhdm` (смещение и флаг доступности), `paging_mode`, `framebuffer`
   (адрес/ширина/высота/pitch/bpp), `rsdp`, `tsc_hz`, `entropy` (опционально),
   `modules`.
2. Валидация: диапазоны не пересекаются и лежат в физическом адресном пространстве;
   `hhdm` выровнен; framebuffer имеет ненулевые размеры; `usable` считается функцией.
3. Хелперы: суммарный usable, поиск самого большого диапазона, форматирование сводки
   (для лога ядра) — без аллокации, в буфер.
4. Тесты на хосте: корректная карта, пустая карта, пересечения, нулевой framebuffer,
   переполнение сумм, граничные адреса.
