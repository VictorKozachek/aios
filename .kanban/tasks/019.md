## Задача

P3: HTTP API прототипа — тот же управляющий контур, но для программ.
Часть схемы из docs/PROTOTYPE.md §2 (api/) и задела под будущий AIOS-API
(docs/ARCHITECTURE.md §8).

### Что сделать

1. **Сервер** на std (без внешних фреймворков, как modeld): слушает `127.0.0.1:8088`,
   минимальный HTTP/1.1: keep-alive не обязателен, chunked не нужен.
2. **Эндпоинты** (подмножество, достаточное для клиентов OpenAI SDK):
   - `POST /v1/chat/completions` — `{model, messages, stream}`; потоковый ответ SSE
     (`data: {"choices":[{"delta":{"content":"..."}}]}` … `data: [DONE]`), при `stream:false` —
     обычный JSON; `usage` из ollama (prompt/completion).
   - `GET /v1/models` — список доступных моделей из ollama.
   - `GET /health` — `{status, model, ollama}` (понятный ответ, если ollama лежит).
   - `GET /metrics` — простой текст: запросы, токены, средняя латентность.
3. **Аутентификация**: токен из `AIOS_API_TOKEN` (если задан — требовать `Authorization: Bearer …`,
   иначе 401). Если не задан — только loopback и предупреждение в лог.
4. **Связь с памятью** (если 017 уже влита): контекст собирать тем же `build_context`,
   чтобы API и консоль отвечали одинаково. Если 017 ещё не влита — оставить TODO и
   описать в отчёте, как подключим.
5. **Тесты**: парсинг запроса/ответа, SSE-формирование, 401 без токена, health при
   недоступной ollama (мок), метрики считаются.

### Приёмка

- `curl -s localhost:8088/v1/models` отдаёт JSON со списком моделей;
- `curl -N -s localhost:8088/v1/chat/completions -d '{"model":"qwen2.5:0.5b","messages":[{"role":"user","content":"привет"}],"stream":true}'`
  печатает поток `data: …` и `[DONE]`;
- без токена (когда `AIOS_API_TOKEN` задан) — 401;
- `cargo test` в prototype/ зелёный.

### Границы

`prototype/api/**` + член в `prototype/Cargo.toml`. Корневой Cargo.toml, kernel/, libs/ — не трогать.
