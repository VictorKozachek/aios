## Задача

Начало M1: многопроцессорность и планировщик. База — `v0.1` после слияния #004 (T3) и #005 (T4b).
Worktree и ветку создам отдельно, когда база будет влита.

### Что сделать

1. **SMP bring-up через Limine MP**: получить список CPU из ответа `MP`, поднять AP —
   им нужны собственные стеки, GDT/TSS (у каждого свой `rsp0` в TSS), IDT общая.
   AP стартуют в защищённом режиме по `goto_address` — проверить порядок входа.
2. **per-CPU структуры**: `cpu_id` через CPUID/GS-base, указатель на текущий CPU,
   стек прерываний. Доступ из кода — через `this_cpu()`.
3. **Таймер**: LAPIC timer в один выстрел/периодический, тики в счётчик.
4. **Планировщик**: простейший round-robin по kernel-потокам: `spawn(fn)`, переключение
   контекста на тике (сохранение rax..r15, rip, rflags, rsp), idle-поток (`hlt`).
5. **Синхронизация**: спин-мьютекс и счётчики с `lock`-префиксами; консоль уже с мьютексом.
6. **Диагностика в лог**: число поднятых AP, тики за 1 с (проверка частоты), число
   переключений, список потоков.

### Приёмка

- `make qemu` с `-smp 4`: в логе `smp: 4/4 CPUs online`, тики идут, планировщик
  переключает минимум 2 потока (видно по счётчикам);
- `AIOS_SMP_TEST=1`: два потока инкрементируют свои счётчики и оба растут;
- `make smoke` 11/11 (маркеры сохраняются);
- прерывания включаются ТОЛЬКО после установки IDT и таймера — проверить, что
  `sti` стоит после инициализации, и что ранний таймер не роняет загрузку;
- `cargo check --target x86_64-unknown-none` зелёный.

### Границы

`kernel/src/smp/**`, `kernel/src/sched/**`, `kernel/src/arch/x86_64/{apic,timer}.rs`,
`kernel/src/main.rs` (инициализация). Не переписывать boot/, mm/, console/ по существу.
