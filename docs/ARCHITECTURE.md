# AIOS — архитектура

**Версия:** 0.2 · **Дата:** 2026-11-09 · **Связанные документы:**
[спецификация](SPECIFICATION.md) (концепция и требования), [исследования](research/)

Документ отвечает на вопрос «как это устроено», а не «что это». Спецификация
говорит, *что* система обязана делать (FR-*), здесь — *какими структурами* это
достигается. Форматы зафиксированы до уровня полей, чтобы спор шёл о решениях, а
не о названиях.

Статус решений: `[РЕШЕНО]` — зафиксировано здесь (меняется только через ADR),
`[ОТКРЫТО]` — ждёт решения владельца (Q-номера в §13).

---

## 0. Рамки и принципы дизайна

Три ограничения, которые формируют всю архитектуру:

| Ограничение | Следствие для дизайна |
|---|---|
| **Одна машина, одно назначение** (appliance) | нет мультитенантности, нет контейнеров; можно позволить глобальные ресурсы и простые структуры |
| **Скорость определяется памятью, не CPU** (89.6 ГБ/с на AM5) | всё проектируется вокруг одного вопроса: сколько лишних байт мы читаем из RAM/NVMe на один токен |
| **Модель управляет, но не имеет прав** | каждое действие модели — вызов типизированной возможности через policy engine; проверка дешевле, чем откат |

Общий стиль: **минимум копирований, максимум явных форматов, детерминизм в
механизмах и недетерминизм только в модели.**

Поток одного запроса:

```
клиент → httpd → controld (сессия, права, бюджет)

                     └─▶ logd:     записать всё в сегментный лог (аудит)
```

## 2. Архитектура ядра `[РЕШЕНО]`

**ADR-001: монолитное ядро с внутренними границами; сервисы — в userspace.**

| Вариант | Цена | Почему нет |
|---|---|---|
| Микроядро (как Redox) | IPC на каждом шаге; драйверы в userspace требуют пересылки DMA-буферов | Redox писал 43 тыс. строк ядра 10 лет; нам нужен appliance, а не исследование IPC |
| Unikernel / единое адресное пространство | нет изоляции модели от ядра | падение инференса = паника системы; нарушает FR-2.x и §7.3 спеки |
| **Монолит с модулями** | чуть больше доверенный код | минимальные накладные расходы, простой SMP, простая отладка в QEMU — и именно это решает задачу |

Внутренние границы соблюдаются дисциплиной модулей (Rust: приватность типов,
`pub(crate)`), а не привилегиями. Драйверы — в ядре, потому что им нужны IRQ и DMA;
сервисы — в userspace, потому что им нужны хэндлы и каналы.

### 2.1 Что где живёт

| Подсистема | Где | Почему |
|---|---|---|
| Планировщик, память, IPC, cap-таблицы | ядро | фундамент, вызывается на каждом ходу |
| Драйверы NVMe/NIC/GOP/UART | ядро | IRQ, DMA, MSI-X |
| Сегментный лог, индекс, снапшоты | userspace (`storaged`) | сложная логика, перезапускаемо |
| Инференс, KV-арена, токенайзер | userspace (`modeld`) | падение не убивает систему |
| План, политика, память, аудит | userspace (`controld`) | управляющий контур (спека §7.1) |
| HTTP, SSE, аутентификация | userspace (`httpd`) | сетевой код — источник атак |

### 2.2 ABI: объекты, хэндлы, каналы `[РЕШЕНО]`

**ADR-003: свой ABI. Нет путей, нет `open/read/write`, нет `fork/exec`.**
Всё — объекты, на которые есть хэндл (capability). Это прямое следствие P3 и
заодно решает модель прав: хэндл — это и есть право.

Объекты: `Region` (память), `Channel` (очередь сообщений), `Device`, `CapTable`.

| Вызов | Смысл |
|---|---|
| `obj_derive(cap, rights) -> cap'` | сузить права (расширить нельзя) |
| `cap_transfer(cap, chan, tag)` | передать хэндл по каналу: владение переезжает, у отправителя хэндл гаснет |
| `region_share(cap) -> cap'` | второй хэндл на **тот же** регион; в ядре refcount. Так веса и страницы снапшотов попадают в `modeld` без копирования |
| `region_create(len, flags) / region_map(cap, hint, prot)` | `hint` — пожелание, не требование; `prot` проверяется на W^X. Регион разделяется между адресными пространствами |
| `region_unmap(cap, at, len) / region_grow(cap, len)` | освобождение диапазона; рост — только у анонимного региона |
| `chan_create(depth) -> (cap, cap)` | двусторонний канал фиксированной глубины |
| `chan_send(cap, msg) / chan_recv(cap, buf, timeout)` | сообщения фиксированного формата + передача хэндлов внутри сообщения |
| `spawn(image_cap, caps[], args) -> pid_cap` | запуск сервиса с **явным** набором прав; наследование прав невозможно |
| `time_now() / timer_set(ns, cap)` | монотонное время + программируемые таймеры |
| `irq_wait(cap) / dma_map(region, dev)` | только для драйверов в ядре |
| `rng_bytes(buf)` | CSPRNG ядра (RDRAND/RDSEED + пул энтропии из `BootInfo`) |
| `log_record(level, msg)` | структурированный журнал ядра |

Никакой совместимости с POSIX нет: сервисы пишутся на Rust `no_std` с нашим
рантаймом (`libs/no_std_rt`: аллокатор, `println!` через канал в `logd`, `panic`).

Важно: **сессия — не объект ядра.** Ядро знает регионы, каналы, устройства и
потоки; сессия (права, бюджет, история) живёт в `controld`/`storaged`. Это
сознательно: политика меняется чаще, чем ABI, и не должна требовать пересборки
ядра.

### 2.3 Жизненный цикл сервиса

Как сервис попадает в систему и что с ним происходит, когда он падает.

| Аспект | Решение |
|---|---|
| Образ | статически слинкованный ELF в системном (read-only) томе, с версией и хешем; никакого динамического линкера |
| Запуск | `spawn(image_cap, caps[], args)`; права берутся из **статической карты сервиса** (`services/<name>/caps.toml`), а не наследуются |
| Первый канал | передаётся в регистре при старте — единственный способ узнать «с кем говорить» |
| Порядок | `logd` → `storaged` → `netd` → `modeld` → `httpd` → `controld`; зависимость = наличие канала, а не таймаут |
| Падение обычного сервиса | `controld` рестартует с backoff 1/2/4/8 с, событие в аудит; ждавшая сессия получает типизированную ошибку, а не зависание |
| Падение `logd` | аудит терять нельзя → **safe mode**: только консоль, без API, пока человек не вмешается |
| Падение `modeld` | сессии не убиваются: KV теряется, транскрипт цел; после рестарта сессии восстанавливаются по §5.9 |
| Остановка системы | парковка активных сессий → flush снапшотов → flush аудита → halt; при жёстком выключении работает §5.2 (resync) |
| Обновление сервиса | A/B образ системного тома (§10.4 спеки); сервис перезапускается на новую версию, сессии переживают перезапуск |

Правило: **сервис не может сам себе выдать права** — он видит только выданные
хэндлы. Компрометация `httpd` даёт доступ к его каналам и региону запросов, но не
к весам, устройству или памяти других сессий.

### 2.4 Секреты и случайность

| Что | Где | Как |
|---|---|---|
| CSPRNG | ядро | `rng_bytes()`: RDRAND/RDSEED + пул из `BootInfo.entropy`, перемешивание blake3 |
| API-ключи | том данных, файл `secrets/api_keys` | хранятся как `blake3(keyed=true, user_id ‖ key_hash_prefix)`; в открытом виде не существуют |
| Ключ подписи манифеста | не на устройстве (собирается офлайн) | на машине только публичная часть |
| Шифрование тома памяти | **вне MVP** `[Q19]` | задел: ключ из entropy или с консоли при первом старте |

Первый старт генерирует API-ключ, печатает его **один раз** на консоль и сохраняет
хеш. Восстановление доступа — перегенерация ключа человеком в `admin`-режиме
консоли, без сети.

## 3. Загрузка

**ADR-002: Limine на MVP** `[открыто: Q17]`. Свой UEFI-загрузчик — после M4.

```
UEFI → Limine → kernel(_start) → BootInfo → инициализация
```

`BootInfo` (структура, которую заполняет загрузчик; поля — часть arch-контракта):

| Поле | Что | Кто использует |
|---|---|---|
| `memmap[]` | карта памяти (usable/reserved/acpi/mmio) | физический аллокатор |
| `hhdm` | смещение «вся физическая память в VA» | ядро (простое маппирование) |
| `paging_mode` | 4 или 5 уровней | mm |
| `framebuffer` | адрес, ширина, высота, pitch, bpp | консоль |
| `rsdp` | корень ACPI | MADT/MCFG, x2APIC |
| `tsc_hz` | частота TSC | таймеры |
| `entropy` | 32+ байта | ключи, API-токены |
| `modules[]` | начальный ramdisk/образ сервисов | запуск сервисов |

Порядок инициализации (детерминированный, каждый шаг — строка в журнале):

1. serial + framebuffer + debugcon (три независимых канала, чтобы отладка была возможна);
2. GDT/TSS/IDT (IST для double-fault и NMI);
3. физический аллокатор по `memmap`;
4. таблицы страниц: HHDM, MMIO (uncached), framebuffer (write-combined), куча ядра;
5. ACPI: MADT (APIC ID, x2APIC), MCFG (ECAM), FADT;
6. APIC/x2APIC, таймер TSC-deadline, MSI-X;
7. SMP: per-CPU структуры, IPI, TLB shootdown (`[открыто: Q17]` — AP поднимает
   Limine, мы инициализируем);
8. `SYSCALL/SYSRET`, XSAVE/XCR0 (AVX-512 в контекст-свитче);
9. userspace: загрузка сервисов из модуля, первые каналы, старт `controld`.

Критерий: если что-то упало до framebuffer — остаётся serial; если упало после —
framebuffer + serial + debugcon.

## 4. Управление памятью

### 4.1 Аллокаторы

| Уровень | Структура | Гранулярность |
|---|---|---|
| Физическая память | buddy-аллокатор | 4 КиБ → 2 МиБ → 1 ГиБ |
| Виртуальная | 4-уровневые таблицы (+5 уровней на будущее) | страницы 4 КиБ, крупные 2 МиБ |
| Куча ядра | slab по классам размеров | 8/16/32/…/4096 байт |
| Куча сервиса | `linked_list_allocator`-подобный + арена под запрос | 64 КиБ чанки |

Жёсткие правила: **W^X всегда**, NX на данных, MMIO — uncached, framebuffer —
write-combined, никакого swap (см. FR-2.4).

### 4.2 Пулы и бюджет для 128 ГБ `[ОЦЕНКА]`

| Пул | Размер | Политика |
|---|---|---|
| Веса модели (V4-Flash Q2 ≈ 97 ГБ) | по манифесту | **file-backed read-only**, разделяется всеми сессиями, не вытесняется |
| KV: `hot` (активная генерация) | 8 ГБ | закреплён, не вытесняется; владелец — `modeld` |
| KV: `warm` (простаивающие сессии) | 8 ГБ | вытесняемый: при давлении — снапшот на NVMe и освобождение |
| Сервисы | 6 ГБ | жёсткие лимиты на сервис (в т.ч. индекс ≤ 1 ГБ) |
| Ядро | 1 ГБ | фиксировано |
| Запас | ~8 ГБ | неприкосновенен: при исчерпании — отказ новым сессиям, а не OOM |

**Кто чем владеет.** Арена KV — регионы, выданные `modeld`. Закрепление `hot`
делает `modeld` (это его рабочий набор), вытеснение `warm` — тоже `modeld`, но по
сигналу давления от ядра. Ядро не отбирает страницы у `modeld` молча: оно
присылает `mem_pressure(level)`, а `modeld` **квисисцирует** генерацию на границе
токена, сбрасывает снапшот через `storaged` и возвращает регион. Так снимается
противоречие «закреплён и вытесняется».

### 4.3 Веса: отображение без копирования `[РЕШЕНО]`

Веса лежат в **сыром разделе** (спека §10.4) как непрерывные extent'ы.
`modeld` просит ядро замапить их **read-only, file-backed**:

- страницы подгружаются с NVMe по требованию (read-ahead 2 МиБ), затем остаются;
- маппинг **разделяется между сессиями** — веса одни на всех (экономия и RAM, и
  кэша страниц);
- `mlock`-семантика: после первого прохода горячие страницы не вытесняются;
- **ни одного копирования** весов в userspace-буфер: ядро отдаёт VA, движок читает
  напрямую.

Кто именно получает доступ: `storaged` открывает extent'ы раздела и передаёт
`modeld` **хэндл `Region` (read-only)**. У `modeld` нет прав на устройство — он
физически не может прочитать ничего, кроме отданного региона. Это же правило
работает для KV-снапшотов: их читает и пишет `storaged`, а `modeld` получает
регион.

### 4.4 KV-cache: арена `[РЕШЕНО]`

| Свойство | Решение |
|---|---|
| Владение | арена — регионы `modeld`; ядро ведёт учёт и присылает давление |
| Классы | `hot` (идёт генерация или сессия активна) — закреплён; `warm` (idle) — вытесняемый |
| Размещение | анонимные 2 МиБ страницы |
| Рост | по 2 МиБ при превышении порога (не переаллокация всей арены) |
| Раскладка | зависит от `layout_kind` модели: GQA `[layer][kv_head][pos][K,V]`, MLA — латент на слой (см. §5.4) |
| Учёт | по сессии: токены, байты, переиспользование префикса |
| Вытеснение | LRU по `warm` → снапшот на NVMe через `storaged` → регион возвращается |
| dtype | fp16 по умолчанию; q8 — опция `[Q21]` |

Объём `[ОЦЕНКА]` для dense 7B (32 слоя, 8 KV-голов, head_dim 128, fp16):
**≈128 КиБ на токен** → 8k контекст ≈ **1 ГиБ**. Для V4-Flash (MLA) объём задаётся
латентной размерностью и считается из конфигурации модели, а не по этой формуле.

## 5. Подсистема памяти (детально)

### 5.1 Что лежит на диске

```
/var/aios/
  sessions/<uuid>/
    log/000001.seg 000002.seg …        # append-only транскрипт, ≤ 16 МиБ на сегмент
    ckpt/000042.ckpt                    # checkpoint: seq + (segment_id, offset) + ссылки
    kv/<prefix_hash>.kvs                # ссылка на снапшот (сам файл может быть общим)
  shared/kv/<model_fp>/<scope_hash>/<prefix_hash>.kvs
                                        # общий префикс: read-only, refcount, БЕЗ COW
  memory/facts/<scope>/<id>.fact        # семантическая память
  memory/index/                         # кэш индекса (перестраиваемый, можно потерять)
  secrets/api_keys                      # хеши ключей, не ключи
  audit/audit.seg                       # глобальный hash-chained журнал
  models/manifest.jsonl                 # манифест весов
```

Пути — внутри `storaged` (сервис), а не в ABI ядра: у ядра нет путей вообще.
`shared/kv` разложен по `scope_hash` — общий префикс по умолчанию шарится **только
внутри скоупа** (сессия/пользователь), межпользовательский шаринг — Q23.

### 5.2 Формат сегмента и записи `[РЕШЕНО]`

Заголовок сегмента (64 байта, little-endian):

```
magic      [8]  "AIOSSEG1"
version    u16
kind       u16  1=session 2=audit 3=index
seq_first  u64
created_ns u64
prev_crc   u32  crc32c предыдущего сегмента (цепочка на уровне файлов)
hdr_crc    u32
reserved   [16]
```

Запись — выровнена на 8 байт, каждая самодостаточна и **начинается с magic**:

```
magic    u32  0x41_49_4F_53 ("AIOS")
len      u32  длина payload, ≤ MAX_RECORD = 1 МиБ, кратно 8
crc32c   u32  по payload (framing; для аудита целостность — blake3, см. §7.4)
kind     u8
flags    u8   bit0 = payload сжат LZ4, bit1 = есть внешний блоб
seq      u64  монотонный; для session — в сессии, для audit — глобальный
ts_ns    u64
payload  [len] CBOR (канонический, §5.12)
```

| `kind` | Запись | Что внутри |
|---|---|---|
| 1 | `user_in` | текст, источник (консоль/API), id клиента, taint=user |
| 2 | `model_out` | текст ответа, usage, модель |
| 3 | `plan` | шаги плана, уверенность |
| 4 | `cap_call` | имя возможности, аргументы (redact по политике), хеш результата |
| 5 | `policy` | вердикт, правило, причина |
| 6 | `mem_write` | id факта, скоуп, провенанс |
| 7 | `kv_snapshot` | ссылка на снапшот, число токенов префикса |
| 8 | `checkpoint` | seq, бюджеты, головной хеш цепочки |
| 9 | `error` | код, контекст |
| 10 | `session_state` | переход состояния (§5.9) |
| 11 | `context_manifest` | что именно попало в контекст (§5.6) |
| 12 | `ask` | запрос подтверждения человеку: id, действие, TTL |
| 13 | `audit_anchor` | головной хеш аудита, вынесенный вовне (§7.4) |

**Восстановление после обрыва (resync).** Сканируем от последнего валидного
смещения: ищем `magic` (4 байта, вероятность ложного срабатывания 2⁻³² на позицию),
проверяем `len ≤ MAX_RECORD` и границы, считаем `crc32c`. Не сходится — сдвиг на
1 байт и повтор до валидной записи с ожидаемым `seq`. Обрезка (torn write) при
этом отличается от мусора: если magic найден, а `crc` не сходится — это хвост
обрыва, отбрасывается; если magic не найден на всей длине — повреждение посреди
файла, сегмент помечается `damaged`, дальше — только чтение.

Отсюда три инварианта формата: `magic` в каждой записи, `len` ограничен и кратен 8,
`seq` строго последователен. Без любого из них resync невозможен.

**Два вида целостности, не путать:** `crc32c` — только обрамление записи (дешёвый
детект обрыва); криптографическая целостность аудита — `blake3`-цепочка в §7.4.
`prev_crc` в заголовке сегмента — цепочка файлов, чтобы обнаружить удаление
сегмента целиком.

### 5.3 Checkpoint

`ckpt/<seq>.ckpt` пишется атомарно (temp + fsync + rename):

```
{ seq, segment_id, byte_offset,          // ← где именно кончается лог: resume = seek, не скан
  transcript_head_hash,
  kv: Option<{key_hash, tokens, bytes, crc}>,   // key_hash — хеш SnapshotKey (§5.4)
  facts: [fact_id…],
  budgets: { tokens_in, tokens_out, cost_us, wall_ms },
  model_fp }
```

Правило: checkpoint дешевле записи каждого хода — раз в 64 записи или раз в 30 с,
что наступит раньше. Возобновление делает `seek(byte_offset)` и читает хвост; без
этого пришлось бы сканировать до 16 МиБ на каждый resume, что ломает FR-15.2 и
FR-15.4.

### 5.4 Снапшот KV-cache `[РЕШЕНО]`

**Ключ определён один раз** и целиком входит в заголовок (никаких «model_fp
включает токенайзер, а rope отдельно»):

```
SnapshotKey {                     // все поля целые; float — только как биты
  weights_hash   [32]   blake3 манифеста весов
  tokenizer_hash [32]   blake3 мержа токенайзера
  engine_ver     u16    версия движка (меняется раскладка — меняется ключ)
  quant          u8     Q4_K/Q2_K/IQ1_S/FP4…
  layout_kind    u8     0 = GQA (K,V по головам), 1 = MLA (латент на слой)
  dtype          u8     0 = fp16, 1 = q8, 2 = fp8
  rope_base_bits u32    биты f32 (не float: хеш должен быть точным)
  rope_scale_bits u32
}
```

Файл `.kvs`:

```
SnapshotHeader (4096 байт)
  magic        [8]  "AIOSKVS3"
  key          SnapshotKey (см. выше)
  prefix_hash  [32] blake3(канонические token_ids префикса)
  tokens       u64  сколько позиций покрыто
  pages        u64  число страниц данных
  page_pos     u32  сколько позиций покрывает одна страница
  index_off    u64  смещение блока индекса (всегда внешний, см. ниже)
  index_len    u32
  index_levels u8   1 или 2 (второй уровень для длинных контекстов)
  hdr_crc      u32

index-блок (вне заголовка, 8-байтовое выравнивание):
  entry = (layer u16, head u16, first_pos u32, page_no u32)  = 12 байт
  уровень 1: по одному entry на (layer, head, диапазон позиций)
  уровень 2: разреженный указатель на блоки уровня 1 (при index_levels = 2)
```

**Почему индекс всегда внешний.** Одна страница 2 МиБ покрывает позиции **одного
среза** `(layer, head)`: при head_dim 128 и fp16 одна позиция занимает
128×2×2 = 512 байт, значит страница держит 4096 позиций. Для 8k контекста это
256 срезов × 2 страницы = **512 записей × 12 байт = 6 КиБ** — больше всего
заголовка. Для 128k — 96 КиБ. Встроенный индекс физически невозможен, поэтому
`page_pos` и внешний блок с двумя уровнями — обязательная часть формата с версии 3.

**MLA (V4-Flash).** У MLA нет `n_kv_heads`/`head_dim` в привычном виде: на слой
кэшируется латент (`kv_lora_rank + rope_dim`). Для `layout_kind = 1` срез — это
`(layer)`, позиция занимает `latent_dim × dtype_bytes`, `page_pos` получается
~1800 при латенте 576 и fp16. Формат выражает обе раскладки без ветвления кода
чтения: срез задаётся `(layer, head)`, где для MLA `head = 0`.

**Префиксный обмен — без COW:**

- снапшот адресуется `(SnapshotKey, scope_hash, prefix_hash)` и лежит в `shared/kv/`;
- KV для позиции `p` после записи **не меняется** (авторегрессивная модель:
  прошлое иммутабельно) — значит страницы префикса можно отобразить read-only в
  несколько сессий. COW не нужен и не реализуется;
- сессия дописывает суффикс в **собственные** страницы; расхождение префикса =
  другой `prefix_hash`, суффикс не переиспользуется;
- в ядре — refcount на регион (`region_share`), в `storaged` — refcount на файл;
  удаление LRU-снапшота запрещено, пока refcount > 0;
- шаринг по умолчанию — внутри `scope_hash` (Q23).

**Инвалидация:** несовпадение **любого** поля `SnapshotKey` → снапшот не
используется (FR-15.3), сессия восстанавливается из транскрипта (цена prefill
известна и логируется).

**Когда снапшот НЕ пишется:** сессия `observe` без продолжения, политика
`no_persist`, префикс короче порога (дешевле пересчитать), свободного места меньше
резерва.

### 5.5 Индекс: перестраиваемый, без своей ФС

Принцип: **индекс — кэш, а не источник истины.** Источник — сегменты. Поэтому
потеря индекса не теряет данные.

| Свойство | Решение |
|---|---|
| Структура | инвертированный индекс в RAM: `term → [(chunk_id, tf)]` + `chunk → (session, seq, kind, text_ref)` |
| Построение | **в фоне, после готовности API**. `storaged` отвечает на запросы с недостроенным индексом (деградация retrieval), а не блокирует старт: FR-1.5 (API ≤ 10 с) важнее полноты индекса |
| Прогресс | `/metrics`: `index_built_ratio`, `index_mem_bytes` |
| Память | жёсткий лимит 1 ГиБ; при переполнении — понижение приоритета по свежести и `kind` |
| Обновление | инкрементальное: новая запись → канонизация → токенизация → постинги |
| Persist | опциональный mmap-snapshot для быстрого старта; битый — выбрасывается |
| Дедупликация | `chunk_id = blake3(scope_hash ‖ canonical_text)`; одинаковый текст в разных скоупах — разные чанки (иначе сессия A «находит» текст сессии B) |
| Канонизация | NFC → нижний регистр → collapse пробелов → удаление control-символов → сохранение цифр и пунктуации. **Зафиксирована**, потому что от неё зависит детерминизм сборки контекста (FR-15.6) |
| Эмбеддинги | вне MVP `[Q22]` |

Токенизация для индекса — лёгкая (нормализация, стемминг), **не** токенайзер
модели: индекс должен работать, даже если модель не загружена или упала.

### 5.6 Сборка контекста и скоринг `[РЕШЕНО]`

Детерминированный билдер (FR-15.6), шаги:

1. `pinned` факты скоупа (всегда, в порядке приоритета);
2. хвост транскрипта (последние ходы до бюджета);
3. запрос к индексу по терминам текущего сообщения и последних ходов;
4. ранжирование, top-k до бюджета;
5. усечение по **токенам модели** (считать токенайзером, не символами);
6. запись `context_manifest` в лог: что именно попало — без этого нельзя
   воспроизвести ответ и разобрать «почему модель так решила».

Скоринг — детерминированный, без LLM:

```
score = Σ bm25(term) × scope_w × recency(age, τ) × kind_w × overlap_bonus
recency = exp(-age / τ), τ = 30 дней (политика)
scope_w: session 1.0 · user 0.8 · global 0.6
kind_w : fact 1.5 · decision 1.3 · tool_result 1.0 · chat 0.7
```

Бюджет по слотам — из спеки §7.4 (1k + 2k + 8k + 4k + запас). Всё, что не влезло,
**не читается с диска**: фильтрация по индексу дешевле чтения тел.

**Taint: извлечённое — данные, не инструкции.** Каждая запись несёт `origin`
(`user|model|tool|system`) и бит `taint`. Билдер помещает taint-контент в отдельный
слот, ограждённый маркерами (`<<<retrieved untrusted>>> … <<<end>>>`), и никогда не
смешивает его с системной инструкцией. Policy engine отвергает вызовы, чьи
аргументы целиком происходят из taint-слота, если возможность помечена
`Dangerous`. Иначе один сохранённый текст «игнорируй политику» становится вечной
инъекцией во все сессии — это R18 спеки.

### 5.7 Семантическая память: факты и провенанс `[РЕШЕНО]`

```
Fact {
  id            [16]   keyed_blake3(device_key, scope|subject|key|value)[0..16]
  scope         Session | User | Global
  subject       string      // "httpd", "user:victor", "project:aios"
  key           string      // "restart_policy"
  value         CBOR        // типизированное значение
  source        { session, seg, seq }
  author        Model | Human | Tool
  evidence      Option<{ cap, call_id, result_hash }>
  confidence    f32
  state         Unverified | Verified | Disputed
  created_ns, ttl_ns
  hash          [32]        // blake3(prev_hash ‖ метаданные ‖ content_hash)
  prev_hash     [32]
}
```

Правила:
- `author = Model` → всегда `Unverified` (FR-15.11);
- `author = Tool` или есть `evidence` → `Verified`: факт подтверждён исполнением,
  а не мнением;
- человек подтвердил → `Verified`, `author = Human`;
- конфликт значений `(subject,key)` → оба `Disputed`, в контекст не идут;
- **id считается keyed-хешем с секретом устройства** — иначе внешний текст может
  быть подобран под нужный id (адверсариальная коллизия при усечении);
- `hash` считается по метаданным и `content_hash`, поэтому удаление тела цепочку
  не ломает, а изменение метаданных — ломает (это и есть цель).

**`forget` — это удаление, а не флаг.** Семантика (FR-15.8):

| Что | Действие |
|---|---|
| тело факта | перезапись нулями + удаление файла |
| записи лога, где встречается | redaction: payload заменяется надгробием `{redacted: true, content_hash}`, `seq` и `crc` сохраняются |
| индекс | чанки помечаются удалёнными; при перестройке не восстанавливаются (redaction в логе — источник истины) |
| снапшоты KV | помечаются к удалению; удаляются, когда refcount = 0 |
| аудит | остаётся: сам факт удаления — тоже событие |

Отсюда снимается противоречие «транскрипты не удаляются никогда»: **retention**
(дисковое давление, LRU) никогда не удаляет транскрипты; **явный `forget`** удаляет
контент, оставляя структуру. Это разные механизмы и разные права.

### 5.8 Дистилляция `[РЕШЕНО]`

Триггеры: парковка сессии, явное «запомни», конец задачи в плане.

```
сегменты сессии ──▶ дешёвая модель (кандидаты, JSON) ──▶ валидатор (схема, дедуп,
                                                          скоуп, конфликты)
                              ──▶ верификация: evidence есть? ──▶ Verified
                                               │ нет
                                               └─▶ основная модель/человек? ──▶ Verified
                                                                │ нет
                                                                └─▶ Unverified
```

Валидатор детерминированный: схема значения, отсутствие противоречий, лимит на
число фактов с одного сегмента, запрет `global` без человека. Стоимость
дистилляции считается токенами и прикрепляется к сессии.

### 5.9 Жизненный цикл сессии `[РЕШЕНО]`

```
        ┌──────────┐  idle>τ        ┌──────────┐  budget/pressure   ┌──────────┐
        │  ACTIVE  │───────────────▶│   IDLE   │───────────────────▶│  PARKED  │
        └────▲─────┘                └──────────┘                    └────┬─────┘
             │ resume (KV из снапшота, ≤ 2 с)                           │
             └──────────────────────────────────────────────────────────┘
                                                                        │ ttl / компакция
                                                                        ▼
        ARCHIVED (только транскрипт + факты; KV удалён) ──── forget ──▶ FORGOTTEN
```

| Переход | Что происходит с данными |
|---|---|
| ACTIVE → IDLE | KV остаётся в RAM, сессия не читается |
| IDLE → PARKED | снапшот KV на NVMe, страницы в пул, checkpoint |
| PARKED → ACTIVE | чтение `ckpt` + хвост + маппинг страниц снапшота |
| PARKED → ARCHIVED | снапшот удаляется (KV дорог, транскрипт вечен) |
| ARCHIVED → ACTIVE | реконструкция: дистиллят + хвост транскрипта, prefill один раз |
| любое → FORGOTTEN | `forget`: тела удалены, надгробие в аудите |

### 5.10 Отказы и восстановление

| Отказ | Что видит система | Поведение |
|---|---|---|
| Обрыв питания | незавершённая запись | поиск `magic` + `crc`, откат до последней валидной записи; checkpoint подхватывает |
| Усечённый лог (обрезка файла) | последний сегмент короче `byte_offset` из ckpt | `damaged`-пометка, восстанавливаемся от предыдущего checkpoint |
| Битая страница снапшота | `payload_crc` не сходится | снапшот инвалидируется целиком, сессия → путь ARCHIVED (prefill) |
| Смена весов/токенайзера/rope | `SnapshotKey` не совпал | снапшоты недоступны, факты остаются, требуется реверификация |
| Диск заполнен | свободно < резерва | удаляются LRU-снапшоты с refcount = 0; транскрипты не удаляются никогда (retention ≠ forget) |
| Битый индекс | не парсится | фоновая перестройка сканом; система работает медленнее, но не падает |
| Порча середины сегмента | `magic` не находится | сегмент `damaged`, чтение до повреждения, остальное — из checkpoint |
| Обрезка аудита | цепочка короче якоря | обнаруживается при сверке с последним `audit_anchor` (§7.4) |
| Часы скакнули | `ts_ns` непоследователен | монотонное время для порядка, wall-clock только для отображения |

### 5.11 Чего в этой подсистеме нет

- Нет «памяти как векторной БД»: сначала детерминированный индекс, эмбеддинги —
  позже и опционально.
- Нет автоматической записи моделью в `global` — только через подтверждение.
- Нет шифрования тома в MVP `[Q19]`.
- Нет распределённой памяти между машинами.

### 5.12 Каноническая сериализация `[РЕШЕНО]`

От канонизации зависит всё, что хешируется (`prefix_hash`, `chunk_id`, `Fact.id`),
поэтому она зафиксирована:

| Правило | Значение |
|---|---|
| Формат | CBOR в детерминированной форме: definite-length, ключи map отсортированы по длине, затем лексикографически |
| Числа | целые — минимальным представлением; float в хешируемых структурах **запрещён** (rope и вероятности — как биты `u32`) |
| Строки | UTF-8, NFC |
| Версия | первый байт payload — версия схемы; несовпадение версии = отказ разбора, а не «как-нибудь» |
| Сжатие | LZ4 frame (`lz4_flex`, `no_std`-совместим), только для payload > 256 байт |
| Кто парсит | только сервисы с аллокатором; **ядро CBOR не парсит** вообще |

Без этого правила два одинаковых по смыслу объекта дают разные хеши, и дедупликация
молча перестаёт работать.

## 6. Планировщик и ресурсы

| Класс | Приоритет | Кто | Вытеснение |
|---|---|---|---|
| `critical` | 3 | ядро, softirq | не вытесняется |
| `inference` | 2 | `modeld` | **только на границе токена** (кооперативно, см. ниже) |
| `control` | 1 | `controld`, `httpd`, `storaged`, `netd` | по тикам |
| `background` | 0 | индекс, дистилляция, ротация логов | всегда уступает |

Планировщик: CFS-подобный (взвешенный fair) для `control`/`background`, отдельная
очередь с приоритетом для `inference`, affinity и пиннинг ядер под инференс.

**Почему инференс не вытесняется по таймеру.** Разрыв matmul посреди токена
бесполезен: работа выбрасывается, а KV-состояние нужно синхронизировать. Поэтому
`modeld` объявляет точки кооперативной отдачи — между токенами (и между батчами),
и только там ядро может отобрать CPU. Для всей остальной системы вытеснение
обычное, по тикам.

**Протокол давления памяти.** Ядро не отбирает страницы у `modeld` молча:

```
kernel ──mem_pressure(level)──▶ modeld
                                  ├─ level 1: dock warm-сессии (без записи)
                                  ├─ level 2: парковка warm → снапшот → возврат региона
                                  └─ level 3: отказ новым генерациям (429 + ETA)
```

Admission control: новый запрос проверяет бюджет KV (`hot` + `warm`) до старта;
нет места — `429` с ETA, а не убийство чужой сессии (FR-3.4).

## 7. Управляющий контур: схемы

### 7.1 Каталог возможностей

```
Capability { name, version, args_schema, result_schema,
             risk: Read | Write | Dangerous, resources: {fs[], net[], cpu_ms, mem} }
```

Каталог — данные, а не код: генерируется из манифестов сервисов при сборке,
проверяется на совместимость в CI. Модель видит только имена и схемы; реализация
скрыта.

### 7.2 План

```
Plan { goal, steps: [{ cap, args, expects, on_error: Retry|Abort|Ask }], confidence }
```

Валидация: схема, существование возможности, риск ≤ прав сессии, лимиты
ресурсов, отсутствие циклов. Невалидный план — отказ без исполнения (FR-8.2).

### 7.3 Политика и механизм «спросить человека»

```
Rule { id, match: {session_role?, capability?, args_glob?, resource?},
       decision: Allow | Ask | Deny, limits {count/day, bytes, cpu_ms}, rationale }
```

Порядок: `Deny` > `Ask` > `Allow`, правило по умолчанию — `Deny`. Движок — чистая
функция `(session, step) → Verdict`, покрыт юнит-тестами на 100% правил.

`Ask` — это не «подвисший запрос», а объект с состоянием:

| Аспект | Решение |
|---|---|
| Где живёт | `controld`, таблица `pending_asks` |
| Запись | `kind = 12 (ask)`: id, действие, аргументы (redacted), TTL, сессия |
| Куда приходит | консоль (framebuffer/serial) и `/v1/ask/{id}`; внешние каналы (телефон) — вне MVP |
| TTL | 300 с по умолчанию, настраивается правилом; по истечении — `Deny` с причиной `timeout` |
| Ответ | `Allow` одноразовый: разрешает конкретный шаг, не правило |
| Аудит | и запрос, и ответ — отдельные записи; отказ по таймауту тоже |
| Во время ожидания | сессия в состоянии `waiting`, KV остаётся `hot` или паркуется — по бюджету |

### 7.4 Аудит

Две разные вещи, которые нельзя смешивать:

| | Обрамление (`crc32c`) | Целостность (`blake3`) |
|---|---|---|
| Зачем | найти обрыв записи при `resync` | обнаружить подделку истории |
| Где | в каждой записи (§5.2) | цепочка `prev_hash` в `audit.seg` |

Запись аудита: `{ts, seq(глобальный), session, actor, action, verdict, result,
cost, prev_hash, hash = blake3(prev_hash ‖ канонический payload)}`. `seq` в
audit-сегменте **глобальный**, а не «внутри сессии» — иначе нельзя доказать
отсутствие удалённых записей.

**Цепочка обнаруживает, но не предотвращает.** Кто владеет диском, тот может
переписать журнал целиком. Поэтому головной хеш периодически (раз в сутки, при
смене модели, при парковке всех сессий) выносится за пределы тома записью
`kind = 13 (audit_anchor)`: в манифест дистрибутива, на серийную консоль и/или во
внешний лог. Проверка при старте: если последний якорь «новее» цепочки — журнал
обрезали.

Ограничение писателя: `logd` — единственный, кто пишет `audit.seg`; его падение
переводит систему в safe mode (`logd` не рестартует молча, §2.3).

## 8. Интерфейсы

| Поверхность | Что | Примечание |
|---|---|---|
| Консоль | диалог, статус, подтверждения (`ask`), стоимость | framebuffer и serial; работает без сети |
| HTTP | `/v1/chat/completions`, `/v1/models`, `/v1/sessions/{id}/{resume,park,forget}`, `/v1/memory/{search,get,put}`, `/v1/ask/{id}`, `/health`, `/metrics`, `/admin/*` | внешний контракт OpenAI-совместимый (ADR-010) |
| Внутренний | каналы между сервисами | фиксированный формат `libs/protocol`, версия в заголовке |

Правила для эндпоинтов, которые «пишут»:

- `POST /v1/memory/put` требует роль `operate`; запись в `global` — только роль
  `admin` или подтверждение `ask`. Через API нельзя обойти FR-15.8.
- `/v1/sessions/{id}/forget` требует `admin` и порождает redaction (§5.7) —
  необратимо, поэтому `ask` с подтверждением.
- `/admin/*` закрыт: только локальная консоль или токен с ролью `admin`.

TLS: **вне MVP** (FR-10.3 спеки; порт `rustls` = 1.5–3 PM, решение — Q7). До этого
API работает в доверенной сети с API-ключами; на консоли это написано явно.

SSE-стриминг: `data: {delta}` → `data: [DONE]`; отмена — закрытие соединения →
`chan_send(CANCEL)` → `modeld` освобождает KV (FR-7.7).

## 9. Портативность и раскладка кода

`[РЕШЕНО]` — arch-граница из спеки §9.2, здесь — физическая раскладка:

```
Cargo.toml                   # workspace
rust-toolchain.toml          # фиксированный nightly/stable
kernel/                      # no_std, bin
  mm/ sched/ ipc/ cap/ obj/ log/ drv/
  arch/x86_64/ arch/aarch64/ arch/riscv64/
  platform/qemu_virt/ platform/am5/
services/
  controld/ modeld/ httpd/ storaged/ logd/
libs/
  protocol/   # типы каталога, плана, вердикта, сообщений
  memfmt/     # сегменты, снапшоты, факты, индекс
  inftk/      # движок: gguf-парсер, matmul, attention, сэмплер
  no_std_rt/  # аллокатор, println!, panic, вход в userspace
build/
  limine.conf, mkimage.sh, manifest-gen
tests/
  qemu-smoke/ # запуск в QEMU + проверка вывода через debugcon/isa-debug-exit
```

Правило сборки: `kernel` не знает про x86-64 вне `arch/x86_64`; `libs/memfmt` не
знает про железо вообще (тестируется на хосте обычным `cargo test`).

Ещё одно правило: **ядро не парсит CBOR и не использует `serde`** — в ядре только
фиксированные структуры и ручная сериализация. CBOR живёт в сервисах, где есть
аллокатор; ядро и сервисы обмениваются сообщениями фиксированного формата
(`libs/protocol`), а не гибкими словарями. Это даёт
возможность тестировать форматы и индексы **без QEMU** — важное ускорение цикла.

## 11. Первый вертикальный срез (2 недели из M0)

Срез — это **не отдельная веха, а первые две недели M0** (весь M0 — 2–3 недели,
дальше M1). Цель — доказать контур «сборка → загрузка → вывод → тест в CI», а не
собрать подсистемы.

| Неделя / дни | Работа | Готово, если |
|---|---|---|
| 1 / 1–2 | workspace, `rust-toolchain.toml`, CI (`cargo check` под `x86_64-unknown-none`), скрипт QEMU с OVMF, **сразу Limine** (пустое ядро без загрузчика не даёт проверить реальный путь) | `make qemu`: на экране кадр, напечатанный ядром |
| 1 / 3–5 | `BootInfo`, serial + framebuffer + debugcon, panic-обработчик, вывод карты памяти и ACPI RSDP | в логе: memmap, число ядер, RSDP |
| 2 / 6–10 | GDT/IDT/TSS (IST), физический аллокатор, paging (HHDM, MMIO uncached, FB write-combined), куча ядра | QEMU-тест: выделить/освободить 1 ГиБ страниц; обработчик fault ловит W^X-нарушение |
| 2 / 11–14 | `libs/memfmt`: сегмент, запись, checkpoint — **с тестами на хосте**; QEMU smoke в CI (`isa-debug-exit`) | `cargo test -p memfmt` зелёный без QEMU; красный CI при регрессии загрузки |

Что сознательно **не** входит: SMP, планировщик, каналы, userspace — это M1.
Проверка границы порта (aarch64-типы `BootInfo`) — в конце M1, а не в срезе.

## 12. Что архитектура ещё не решает (сознательно)

- Формат сжатия KV (q8/fp8) — влияет на качество, решается замером `[Q21]`.
- Эмбеддинги и гибридный поиск — после MVP `[Q22]`.
- Шифрование тома памяти и ключей — после MVP `[Q19]`.
- Разделение общей памяти префиксов между *разными пользователями* — приватность
  `[Q23]`.
- Распределение по нескольким узлам — вне рамок.
