# План M0: «Металл» — что делаем первым

Цель M0: ядро загружается на реальной плате (и в QEMU), печатает карту памяти,
ACPI и CPUID; есть физический аллокатор, paging, куча и лог; всё это проверяется
в CI на каждый коммит. Оценка M0 по спецификации — **2–3 недели**.

Здесь — разбивка на задачи. Каждая задача: одна ветка, один worktree, один
исполнитель, чёткие границы файлов.

## 0. Что нужно на машине (один раз)

| Инструмент | Зачем | Статус |
|---|---|---|
| Rust 1.98+ | есть (Homebrew) | ✅ |
| `rustup target add x86_64-unknown-none` | сборка ядра под голое железо | ❌ поставить |
| QEMU (`brew install qemu`) | запуск без риска для железа | ❌ поставить |
| Limine (релиз + `limine` в PATH) | загрузчик | ❌ поставить |
| OVMF (`qemu` ставит `edk2-x86_64-code.fd`) | UEFI-прошивка для QEMU | ❌ вместе с qemu |
| `mtools` (`brew install mtools`) | создание FAT-образа ESP | ❌ поставить |

Проверка после установки: `make qemu` показывает кадр, напечатанный ядром.

## 0.1 Где тестируем

| Среда | Что даёт | Что не даёт | Роль |
|---|---|---|---|
| **QEMU x86-64 + OVMF** (TCG-эмуляция на Mac) | полный путь UEFI → Limine → ядро, ACPI, SMP, virtio, сеть, API | замеры скорости: TCG замедляет в 10–50 раз; реальных драйверов нет | **основной тест M0** и CI |
| **QEMU aarch64 + EDK2** (HVF, нативно на Apple Silicon) | быстрый CI (секунды), проверка arch-границы | x86-специфику не проверяет | второй CI-таргет |
| **Реальное железо** (Ryzen 9, AM5) | настоящие NVMe/NIC, tok/s, термалка, реальный UEFI | риск залочить машину | приёмка M2/M3/M4 |
| Linux-VM (UTM/OrbStack/lima) | изолированный тулчейн | ничего сверх QEMU — ядро всё равно в эмуляторе | не нужна |

Отдельная Linux-машина не требуется: QEMU и есть виртуальная машина, а сборка
идёт host-нативным Rust. Единственный случай, когда Linux-VM полезна — если
brew-пакеты конфликтуют с системой.

## 1. Задачи

### T1. Каркас сборки и запуска (блокирует всё)

| | |
|---|---|
| **Границы** | `Cargo.toml`, `rust-toolchain.toml`, `.cargo/config.toml`, `Makefile`, `build/` , `.github/workflows/` |
| **Что сделать** | workspace; target `x86_64-unknown-none`; `make kernel` (сборка), `make image` (FAT-ESP + Limine + ядро), `make qemu` (запуск с OVMF), `make test`; CI: `cargo check` + сборка образа |
| **Готово, если** | `make qemu` стартует и падает на пустом ядре с понятной ошибкой; `make image` создаёт образ; CI зелёный на пустом ядре |
| **Блокирует** | T2, T6 |

### T2. Загрузка до первого вывода (после T1)

| | |
|---|---|
| **Границы** | `kernel/src/{main.rs, boot/}`, `libs/bootinfo/` |
| **Что сделать** | `_start` по протоколу Limine; запросы: memmap, HHDM, framebuffer, RSDP, TSC, MP; структура `BootInfo`; вывод в serial + framebuffer + debugcon (`0xE9`); panic-обработчик с картой символов |
| **Готово, если** | в QEMU в логе: карта памяти, число ядер, RSDP, версия Limine; на экране тот же текст |
| **Блокирует** | T3, T4 |

### T3. CPU-примитивы (после T2)

| | |
|---|---|
| **Границы** | `kernel/src/arch/x86_64/{gdt,idt,tss,exceptions}.rs` |
| **Что сделать** | GDT + TSS, IDT с IST для double-fault/NMI/page-fault, обработчики исключений с дампом регистров |
| **Готово, если** | намеренный `int3` и деление на ноль дают дамп и не вешают машину |

### T4. Память (после T2, параллельно с T3)

| | |
|---|---|
| **Границы** | `kernel/src/mm/{phys,virt,heap}.rs` |
| **Что сделать** | buddy-аллокатор по memmap; таблицы страниц (HHDM, MMIO uncached, framebuffer write-combined); куча ядра; W^X |
| **Готово, если** | тест в QEMU: выделить/освободить 1 ГиБ страницами; исполнение из heap → page fault, а не тишина |

### T5. Форматы памяти — можно начинать сразу, без QEMU

| | |
|---|---|
| **Границы** | `libs/memfmt/` |
| **Что сделать** | сегмент (заголовок + записи `magic/len/crc/seq`), resync-скан, checkpoint, round-trip тесты, канонический CBOR (правила из ARCHITECTURE §5.12) |
| **Готово, если** | `cargo test -p memfmt` зелёный на хосте; тест «обрыв на каждом байте» проходит; формат совпадает с документом поле в поле |
| **Почему первым** | не требует QEMU и ядра; это то, что дороже всего переделывать позже (архитектура, риск R1 ревью) |

### T6. Smoke-тест в CI (после T1, T2)

| | |
|---|---|
| **Границы** | `tests/qemu-smoke/`, `.github/workflows/ci.yml` |
| **Что сделать** | запуск QEMU с `isa-debug-exit`; тест падает, если ядро не дошло до маркера в логе |
| **Готово, если** | сломанный `BootInfo` (намеренно) роняет CI |

### T7. Сплэш при загрузке (после T1)

| | |
|---|---|
| **Границы** | `kernel/src/splash.rs`, `build/limine.conf`, `kernel/assets/` |
| **Уровень 1 — меню Limine** | фон (`wallpaper`) + строка брендинга: `AIOS · SkyNet v0.0.1` |
| **Уровень 2 — ядро** | после получения framebuffer: центрированный блок — имя, кодовое имя, версия, git-хеш; ниже — строки инициализации (память, ACPI, ядра, TSC) как «прогресс» |
| **Как рисуем** | прямоугольники + встроенный растровый шрифт 8×16 (масштаб 2–4×). Никаких PNG/JPEG в ядре на M0 — нет декодера, не тащим зря |
| **Версия** | не хардкод: Makefile передаёт `AIOS_VERSION` и `GIT_HASH` через окружение сборки, ядро читает `option_env!` |
| **Fallback** | нет framebuffer (serial-only) → одна текстовая строка `AIOS SkyNet v0.0.1 <hash>` |
| **Готово, если** | `make qemu` показывает сплэш; версия совпадает с `git describe`; работает на 1920×1080 и 800×600; до сплэша ≤ 100 мс после framebuffer init; CI падает, если строка версии пустая |

Сплэш **не** добавляет искусственных задержек: время до API не растёт (FR-1.5).
Логотип как 1-битная маска (≈1 КБ, декодер на 20 строк) — после M0, если захочется
картинку вместо текста.

## 2. Порядок и параллельность

```
T1 ──▶ T2 ──┬──▶ T3
            └──▶ T4
T1 ──▶ T6 (после T2)
T5 ── (независима, стартует сразу)
```

Максимум одновременно: **2 исполнителя** (ядро и форматы), плюс один на
инфраструктуру. Три — предел по протоколу.

## 3. Приёмка M0

| Проверка | Критерий |
|---|---|
| Загрузка в QEMU | ≤ 5 с до строки с картой памяти |
| Загрузка на железе | на AM5-плате, Secure Boot выключен, грузится с USB |
| Память | 1 ГиБ выделяется и освобождается; W^X ловится |
| CI | красный при регрессии загрузки |
| Документы | формат сегмента в коде совпадает с `ARCHITECTURE.md` §5.2 |

## 4. Что осознанно не входит в M0

SMP-инициализация (AP поднимает Limine, наши per-CPU структуры — M1), планировщик,
каналы, userspace, драйверы NVMe/NIC, сеть. Всё это M1–M3.
