# AIOS

**Операционная система, которой управляет модель. С нуля. Без Linux.**

> Статус: **концепция v0.1** — ни строки кода ещё не написано, есть только
> спецификация. Лицензия: не выбрана. Язык документа: [English](README.en.md).

---

## Идея в одном абзаце

AIOS — новая операционная система, в которой **LLM является управляющим ядром
системы**, а не приложением поверх неё. Модель DeepSeek понимает намерение
пользователя, планирует действия, вызывает типизированные возможности системы
(файлы, сервисы, сеть, сама себя) и отчитывается о результате. С человеком она
говорит через консоль — как рабочая сессия в агентском харнессе, — а с программами
через защищённый HTTP API. Ядро написано с нуля: свой ABI, свой планировщик, своя
файловая система, свой сетевой стек. Никаких клонов Linux и никаких POSIX-слоёв
«для совместимости».

## Что это значит на практике

| Обычная ОС | AIOS |
|---|---|
| Администратор знает команды и утилиты | Администратор объясняет, что нужно; модель выбирает механизмы |
| Инференс — это процесс, конкурирующий с демонами | Инференс — приоритетный класс: ресурсы, память и ядра зарезервированы под модель |
| Программы общаются через POSIX-примитивы | Программы общаются через API и каталог возможностей |
| Права даются пользователям и процессам | Права даются **сессиям**: модель предлагает, ядро разрешает |
| Аудит — это syslog, который никто не читает | Аудит — основа: каждое действие модели записано с причиной и стоимостью |

## Почему не Linux

Linux — не «новая система», а система с 30-летней обратной совместимостью,
где агент вынужден притворяться процессом, а модель — файлом. AIOS проектируется
под задачу с нуля: примитивы «сессия», «возможность», «намерение», «план» —
естественная часть системы. Плюс контроль: миллионы строк чужого кода в доверенной
базе не нужны, если машина — inference-appliance.

## Ключевые принципы

1. **Модель предлагает — ядро разрешает.** Модель не имеет root: каждое действие
   проходит через policy engine, человека (если действие опасное) и аудит.
2. **Портативность с первого дня.** Один код — разные архитектуры: x86-64 сейчас,
   aarch64 и RISC-V далее, в пределе — собственный силикон. `make image ARCH=…`
   собирает дистрибутив.
3. **Все ресурсы — модели, но по расписанию.** Веса и KV-cache размечаются
   заранее, системный резерв неприкосновенен.
4. **Закрыто по умолчанию.** Только явно открытые порты, только аутентифицированный
   API, только возможности из белого списка.
5. **Демо на каждом шаге.** Веха без работающей демонстрации не считается вехой.

## Как это выглядит

Консоль — это диалог с системой, а не TTY с bash:

```
aios> почему ночью упал сервис httpd?

  [план] 1. log.query: события 02:00–06:00 с уровнем error
         2. metric.query: память и CPU за тот же интервал
         3. отвечу человеку, менять ничего не буду

  [политика] log.query, metric.query → разрешено (только чтение)
  [журнал]   audit://sess-42/steps/1-2

Сервис упал в 03:14: падение при выделении 512 МБ — пул сервисов был исчерпан
фоновой задачей индексации. Модель в этот момент не работала. Рекомендую
ограничить индексатор пулом background — применить? (да/нет)
```

## Железо и модель (контракт MVP)

MVP фиксирует **одну плату** — писать драйверы под всё железо мира
бессмысленно:

| Параметр | Значение MVP |
|---|---|
| Платформа | x86-64, UEFI, AMD Ryzen 9 (AM5, Zen 5, AVX-512 VNNI/BF16) |
| Память | 128 ГБ DDR5-5600 (2 канала, ≈ 90 ГБ/с — это и есть потолок скорости) |
| Накопитель | NVMe ≥ 2 ТБ |
| Модели | dense 7–14B для цикла разработки; **DeepSeek-V4-Flash (291B/13B активных, 82–97 ГБ) как флагман** — 7–10 tok/s |
| Не поддерживается | 671B-семейство (нужно 260–450 ГБ и 8–12 каналов памяти), GPU/NPU-offload |

Скорость генерации упирается в пропускную способность памяти, а не в процессор:
`tok/s ≈ 0.63 × ПСП / размер весов` для dense и `≈ 0.35 × ПСП / активные
параметры` для MoE. Отсюда и выбор моделей.

## Дорожная карта

| Веха | Что получается |
|---|---|
| M0. Металл | ядро грузится на реальной плате (стратегия загрузчика — Q17), память и вывод |
| M1. Ядро | SMP, вытесняющий планировщик, свой syscall ABI, процессы |
| M2. Хранилище | NVMe-драйвер, своя журналируемая ФС, хранилище весов |
| M3. Сеть | драйвер NIC, TCP/IP, DHCP, свой HTTP-сервер |
| M4. Инференс | свой движок, 7–8B, SIMD, KV-cache, OpenAI-совместимый стриминг |
| M5. Провижининг | первая загрузка: скачал модель, проверил подпись, поднял API |
| M6. Управляющий контур | каталог возможностей, политика, аудит, консоль — модель управляет системой |
| M7. Портативность | порт aarch64/RISC-V, сборка дистрибутива под несколько архитектур |

Подробные критерии выхода и оценки — в [спецификации](docs/SPECIFICATION.md).

## Честно о статусе

- Это **концепция**, а не работающая система. Кода нет.
- Оценка пути до MVP-демо — **30–45 человеко-месяцев**: команда 4–6 низкоуровневых
  инженеров ≈ 9–12 месяцев, один человек — 2.5–4 года. Эта цифра получена по
  замерам (800–1300 отлаженных строк/мес, размеры реальных драйверов), а не по
  оптимизму, и записана в спецификации, чтобы не выяснилось в конце.
- Архитектура **не зафиксирована**: открытые вопросы (Q1–Q18) перечислены в
  §15 спецификации. Главный из них — загрузчик: Limine (экономит 4–6 PM, но
  сторонний) против своего UEFI-загрузчика (полностью своё).
